# APT Dependency Visualizer

Практическая работа по конфигурационному управлению, вариант 14.
Инструмент визуализации графа зависимостей пакетов Ubuntu/apt на Python.

## Текущее состояние

Реализованы чтение Ubuntu Packages, рекурсивный BFS, фильтрация,
обработка циклов, тестовый JSON и поиск обратных зависимостей.
На этапе 5 добавлен вывод достижимого графа на языке D2.
Проверены три реальных пакета; их результаты приведены ниже.

Получение зависимостей выполняется собственным кодом на стандартной
библиотеке Python. Индекс загружается один раз за запуск.
Обычный режим печатает только D2, режим `--reverse` — список потребителей.
Результаты этапов 1–4 сохранены в отдельных коммитах.

Сравнение возможностей со штатным `apt-cache` описано по документации.
Фактический запуск `apt-cache` ещё не выполнен: среда разработки — Windows,
доступной Ubuntu/WSL нет. Поэтому практическая проверка пункта 5.4 остаётся
незавершённой; команды для неё подготовлены ниже.

## Требования и сборка

Нужен Python 3.9 или новее. Внешние библиотеки не требуются.
Сборка не нужна: программа запускается непосредственно интерпретатором.
Все команды ниже выполняются из корня проекта.

## Запуск

```powershell
.\run.bat --package bash --repository https://archive.ubuntu.com/ubuntu
```

архитектура `amd64`: `dists/noble/main/binary-amd64/Packages.xz`.

## Настройки

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `--package` | Имя анализируемого Ubuntu-пакета или тестовой вершины | Обязателен |
| `--repository` | URL корня, URL Packages или путь к тестовому JSON | Обязателен |
| `--test-mode` | Читать локальный JSON вместо HTTP-индекса | Выключен |
| `--filter` | Исключать пакеты, имя которых содержит указанную подстроку | Пустая строка |
| `--reverse` | Искать потребителей пакета из `--package` | Выключен |

В обычном режиме имя соответствует правилам Debian/Ubuntu: минимум два
символа, строчные латинские буквы, цифры и знаки `+`, `-`, `.`. Первый
символ — буква или цифра. Тестовые имена состоят из заглавных букв A-Z.

Фильтр применяется к именам вершин с учётом регистра. Пустая строка ничего
не исключает. Пробельный фильтр и управляющие символы запрещены.
Исключённая вершина удаляется из рёбер, обход через неё прекращается.
Её потомок может сохраниться, если к нему есть другая разрешённая ветка.
Если исключён корень, выводится сообщение о пустом графе; для реального
репозитория в этом случае сетевой запрос не выполняется.

В URL корня параметры запроса и фрагмент не допускаются; прямой URL индекса
сохраняется целиком. В тестовом режиме путь должен указывать на доступный файл.

Коды завершения: `0` — успех или справка; `1` — ошибка загрузки или данных;
`2` — ошибка параметров. Сообщения об ошибках выводятся в stderr.

## Чтение реального репозитория

Packages состоит из записей, разделённых пустыми строками. Имена полей
обрабатываются без учёта регистра, продолжения строк сохраняются.
Сжатие gzip, xz или bzip2 определяется по сигнатуре; текст читается как UTF-8.
Сетевой запрос имеет тайм-аут 15 секунд. Ошибки HTTP, соединения, распаковки
и чтения обрабатываются без трассировки исключения.

Граф строится по обязательным полям `Pre-Depends` и `Depends`. Для группы
`first | second` в граф включаются оба имени как варианты выбора.
Условия версий и уточнения архитектуры не входят в имя вершины.
Рекомендации, предложения и конфликты в граф обязательных связей не включаются.

Индекс должен однозначно определять запись каждого имени. Повтор записи
считается ошибкой. Выбор между несколькими версиями одного пакета,
проверка ограничений версий, выбор установленной альтернативы и разрешение
виртуальных имён через `Provides` не выполняются.

Имя зависимости, для которого нет отдельной записи в выбранном индексе,
сохраняется как конечная вершина. Это учитывает виртуальные имена вроде
`awk`, а также границы выбранного индекса. Вершина без исходящих стрелок
означает отсутствие известных приложению связей по этому индексу. Отсутствие записи
начального пакета считается ошибкой.

## Рекурсивный BFS

`build_dependency_graph` получает начальную вершину и функцию загрузки
её прямых соседей. Вложенная функция `visit_level` обрабатывает весь текущий
уровень, собирает следующий и вызывает себя для следующего уровня.
Множество `discovered` заполняется при добавлении вершины в очередь уровня.
Это предотвращает повторную обработку общей зависимости и зацикливание.
Циклические рёбра и ссылки на себя сохраняются в результате.

Глубина рекурсии зависит от числа уровней. Приложение не меняет глобальный
предел рекурсии Python; при его превышении выводится понятная ошибка.

## Формат тестового JSON

```json
{
  "A": ["B", "C"],
  "B": ["C"],
  "C": []
}
```

Ключ — имя пакета, значение — список его прямых зависимостей. Каждое имя
из списка должно присутствовать отдельным ключом. Циклы, ссылки на себя
и несколько несвязанных групп разрешены. Повторяющиеся рёбра удаляются
с сохранением порядка, повторяющиеся ключи JSON считаются ошибкой.
Файл читается в UTF-8, включая UTF-8 с BOM. Тестовый режим не обращается к сети.

## Этап 4: обратные зависимости

Параметр `--reverse` включает поиск пакетов, которые зависят от цели,
указанной через `--package`. Находятся прямые и транзитивные потребители.
Связи разворачиваются, после чего используется рекурсивный BFS этапа 3.
Искомый пакет исключается из собственного списка потребителей даже при цикле.

В тестовом режиме рассматривается весь JSON-репозиторий. В режиме Ubuntu
индекс загружается один раз, после чего анализируются все его разрешённые
пакеты. Обратный поиск охватывает весь выбранный индекс, включая потребителей,
которые не видны при прямом обходе от целевого пакета.

Имена, встречающиеся только в зависимостях, также можно искать: например,
виртуальное имя `awk`. Для альтернатив учитывается каждое объявленное имя,
как и на этапе 3; ограничения версий и выбор провайдера не разрешаются.

Фильтр применяется во время обратного обхода. Исключённая вершина прекращает
обход пути к её потребителям. При наличии другой разрешённой ветки пакет
может остаться в результате. Исключение самой цели обозначается отдельным
сообщением. В режиме Ubuntu исключённая цель не вызывает сетевого запроса.

### Общая зависимость и транзитивный потребитель

```powershell
.\run.bat --package D --repository examples/shared.json --test-mode --reverse
```

```text
Обратные зависимости для D:
- B
- C
- A
```

B и C зависят от D напрямую, A — через них. Вывод упорядочен по уровням BFS.

### Фильтрация одной ветки

```powershell
.\run.bat --package D --repository examples/shared.json --test-mode --reverse --filter B
```

```text
Обратные зависимости для D:
- C
- A
```

Пакет A остаётся доступным по пути обратного обхода D → C → A.

## Этап 5: описание D2

`generate_d2(graph)` получает словарь списков смежности и возвращает текст.
Сначала объявляются все вершины, затем стрелки от пакета к его зависимости.
Ключи `n0`, `n1`, … отделены от подписей: имя `python3.12` не превращается
во вложенный объект D2. Подписи заключаются в кавычки. Циклы и петли
сохраняются, повторяющиеся рёбра удаляются, исходный словарь не меняется.
Порядок вершин соответствует результату BFS, размещение задаёт D2.

Пример: `n0: "bash"` объявляет вершину с подписью bash;
`n0 -> n1` означает, что bash зависит от пакета n1.
`direction: right` задаёт направление размещения слева направо.
Строки с `#` — комментарии. Сообщения об ошибках идут отдельно в stderr.
При исключении корня вывод содержит направление и комментарий о пустом графе.

Требуемый результат программы — текст D2 в терминале.
Устанавливать D2 для генерации текста не требуется. При необходимости
текст можно скопировать в [D2 Playground](https://play.d2lang.com/).
Синтаксис описан в [документации D2](https://d2lang.com/tour/connections/).

### Сопоставление с apt-cache

Штатная команда `apt-cache dotty` создаёт граф в формате Graphviz/DOT.
Для текстового просмотра обязательных связей подходит
`apt-cache depends --recurse --important`: флаг `--important` оставляет
только Depends и Pre-Depends. Это поведение описано в
[руководстве Ubuntu](https://manpages.ubuntu.com/manpages/noble/man8/apt-cache.8.html).

Сопоставление возможностей по документации, а не результаты запуска apt:

| Свойство | Программа | apt-cache |
| --- | --- | --- |
| Язык графа | D2 | Graphviz/DOT у dotty |
| Виды связей | Depends и Pre-Depends объединены | dotty различает Pre-Depends и конфликты |
| Типы вершин | Одинаковые вершины с именами | dotty различает обычные, виртуальные и отсутствующие пакеты |
| Виртуальное awk | Конечная вершина без разрешения Provides | APT знает сведения о провайдерах |
| Источник | Один указанный Packages | Обычно кеш настроенных источников APT |
| Фильтр | Исключение по подстроке и остановка ветки | Такого параметра у dotty нет |

Для практической проверки в Ubuntu 24.04 amd64 выполнить команды ниже.
Они используют отдельный каталог, тот же индекс и пустой статус установки,
чтобы другие источники и установленные версии не меняли сравнение.
`--with-source` позволяет apt-cache читать указанный Packages напрямую.
Команды подготовлены по руководству; в текущей Windows-среде не запускались.

```bash
work=$(mktemp -d)
mkdir "$work/lists"
index=https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.xz
python3 -c 'import sys, urllib.request; urllib.request.urlretrieve(*sys.argv[1:])' \
  "$index" "$work/Packages.xz"
sha256sum "$work/Packages.xz"
options=(
  -o APT::Architecture=amd64
  -o Dir::State::status=/dev/null
  -o Dir::State::lists="$work/lists"
  -o Dir::Etc::sourcelist=/dev/null
  -o Dir::Etc::sourceparts=-
  -o Dir::Cache::pkgcache=
  -o Dir::Cache::srcpkgcache=
  --with-source "$work/Packages.xz"
)
for package in bash gzip gcc-14-base; do
  apt-cache "${options[@]}" depends --recurse --important "$package" \
    > "$work/$package.apt.txt"
  apt-cache "${options[@]}" dotty "$package" > "$work/$package.dot"
  python3 src/main.py --package "$package" --repository "$index" \
    > "$work/$package.d2"
done
echo "Результаты: $work"
```

Проверять нужно имена и направления обязательных связей, а не порядок строк
или расположение узлов. Числа вершин и рёбер программы приведены в таблице.
У bash отдельно проверить цикл libc6/libgcc-s1 и представление awk;
у gzip — общие зависимости и путь gzip → dpkg → tar;
у gcc-14-base — сохранение единственной вершины.
Иные формы и цвета у dotty следуют из обозначений типов пакетов и связей.
Дополнительные провайдеры виртуальных имён, конфликты или другие версии
индекса могут объяснять расхождения с программой; конкретные расхождения
нужно зафиксировать после фактического запуска, а не предполагать заранее.

## Тестирование

```powershell
python -B -m unittest discover -s tests -v
```

Проверяются порядок BFS, циклы, общие зависимости, фильтрация и обход
широких графов, тестовый JSON, однократная загрузка HTTP-индекса, альтернативы
и отсутствующие записи зависимостей. Отдельно проверяется D2:
изолированные вершины, циклы, подписи, повторы и пустой граф.
Тесты используют стандартный `unittest`,
подмену сетевых ответов и временные файлы; доступ к интернету не требуется.

| `print_graph` | Печатает комментарий с корнем и описание D2 |

| `run_test_mode` | Читает JSON и выполняет выбранный обход |
