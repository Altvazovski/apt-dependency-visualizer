# APT Dependency Visualizer

Практическая работа по конфигурационному управлению, вариант 14.
Инструмент визуализации графа зависимостей пакетов Ubuntu/apt на Python.

## Текущее состояние

Реализован этап 3: построение достижимого графа с транзитивными связями
рекурсивным BFS, фильтрация пакетов, обработка циклов и чтение тестового JSON.
Информация реального репозитория загружается и разбирается собственным кодом
с использованием стандартной библиотеки Python. Индекс скачивается один раз
за полный обход; каждую достигнутую вершину алгоритм обрабатывает один раз.

Вывод настроек `ключ=значение` сохранён в коммите этапа 1. Вывод прямых
зависимостей с условиями сохранён в коммите этапа 2. Текущая версия выводит
связи достижимого графа в порядке BFS. Обратные зависимости и вывод D2
относятся к следующим этапам задания.

## Требования и сборка

Нужен Python 3.9 или новее. Внешние библиотеки не требуются.
Сборка не нужна: программа запускается непосредственно интерпретатором.
Все команды ниже выполняются из корня проекта.

## Запуск

```powershell
.\run.bat --package bash --repository https://archive.ubuntu.com/ubuntu
```

Для URL корня используется индекс Ubuntu 24.04 `noble`, компонент `main`,
архитектура `amd64`: `dists/noble/main/binary-amd64/Packages.xz`.
Другой выпуск, компонент или архитектуру можно выбрать прямым URL файла
`Packages`, `Packages.xz`, `Packages.gz` или `Packages.bz2`:

```powershell
$index = "https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.xz"
.\run.bat --package bash --repository $index
```

Запуск через Python:

```powershell
python src/main.py --package bash --repository https://archive.ubuntu.com/ubuntu
```

Проверенный результат для выбранного индекса:

```text
Граф зависимостей для bash:
bash -> libc6, libtinfo6, base-files, debianutils
libc6 -> libgcc-s1
libtinfo6 -> libc6
base-files -> awk, libc6, libcrypt1
debianutils -> libc6
libgcc-s1 -> gcc-14-base, libc6
awk -> нет исходящих связей
libcrypt1 -> libc6
gcc-14-base -> нет исходящих связей
```

Справка:

```powershell
python src/main.py --help
```

## Настройки

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `--package` | Имя анализируемого Ubuntu-пакета или тестовой вершины | Обязателен |
| `--repository` | URL корня, URL Packages или путь к тестовому JSON | Обязателен |
| `--test-mode` | Читать локальный JSON вместо HTTP-индекса | Выключен |
| `--filter` | Исключать пакеты, имя которых содержит указанную подстроку | Пустая строка |

В обычном режиме имя соответствует правилам Debian/Ubuntu: минимум два
символа, строчные латинские буквы, цифры и знаки `+`, `-`, `.`. Первый
символ — буква или цифра. Тестовые имена состоят из заглавных букв A-Z.

Фильтр применяется к именам вершин с учётом регистра. Пустая строка ничего
не исключает. Пробельный фильтр и управляющие символы запрещены.
Исключённая вершина удаляется из рёбер, обход через неё прекращается.
Её потомок может сохраниться, если к нему есть другая разрешённая ветка.
Если исключён корень, выводится сообщение о пустом графе; для реального
репозитория в этом случае сетевой запрос не выполняется.

В URL корня параметры запроса и фрагмент не допускаются; прямой URL индекса
сохраняется целиком. В тестовом режиме путь должен указывать на доступный файл.

Коды завершения: `0` — успех или справка; `1` — ошибка загрузки или данных;
`2` — ошибка параметров. Сообщения об ошибках выводятся в stderr.

## Чтение реального репозитория

Packages состоит из записей, разделённых пустыми строками. Имена полей
обрабатываются без учёта регистра, продолжения строк сохраняются.
Сжатие gzip, xz или bzip2 определяется по сигнатуре; текст читается как UTF-8.
Сетевой запрос имеет тайм-аут 15 секунд. Ошибки HTTP, соединения, распаковки
и чтения обрабатываются без трассировки исключения.

Граф строится по обязательным полям `Pre-Depends` и `Depends`. Для группы
`first | second` в граф включаются оба имени как варианты выбора.
Условия версий и уточнения архитектуры не входят в имя вершины.
Рекомендации, предложения и конфликты в граф обязательных связей не включаются.

Индекс должен однозначно определять запись каждого имени. Повтор записи
считается ошибкой. Выбор между несколькими версиями одного пакета,
проверка ограничений версий, выбор установленной альтернативы и разрешение
виртуальных имён через `Provides` не выполняются.

Имя зависимости, для которого нет отдельной записи в выбранном индексе,
сохраняется как конечная вершина. Это учитывает виртуальные имена вроде
`awk`, а также границы выбранного индекса. Надпись `нет исходящих связей`
описывает связи, известные приложению по этому индексу. Отсутствие записи
начального пакета считается ошибкой.

## Рекурсивный BFS

`build_dependency_graph` получает начальную вершину и функцию загрузки
её прямых соседей. Вложенная функция `visit_level` обрабатывает весь текущий
уровень, собирает следующий и вызывает себя для следующего уровня.
Множество `discovered` заполняется при добавлении вершины в очередь уровня.
Это предотвращает повторную обработку общей зависимости и зацикливание.
Циклические рёбра и ссылки на себя сохраняются в результате.

Глубина рекурсии зависит от числа уровней. Приложение не меняет глобальный
предел рекурсии Python; при его превышении выводится понятная ошибка.

## Формат тестового JSON

```json
{
  "A": ["B", "C"],
  "B": ["C"],
  "C": []
}
```

Ключ — имя пакета, значение — список его прямых зависимостей. Каждое имя
из списка должно присутствовать отдельным ключом. Циклы, ссылки на себя
и несколько несвязанных групп разрешены. Повторяющиеся рёбра удаляются
с сохранением порядка, повторяющиеся ключи JSON считаются ошибкой.
Файл читается в UTF-8, включая UTF-8 с BOM. Тестовый режим не обращается к сети.

## Демонстрация тестовых случаев

Обычный граф:

```powershell
.\run.bat --package A --repository examples/repository.json --test-mode
```

```text
Граф зависимостей для A:
A -> B, C
B -> C
C -> нет исходящих связей
```

Фильтрация пакета B:

```powershell
.\run.bat --package A --repository examples/repository.json --test-mode --filter B
```

```text
Граф зависимостей для A:
A -> C
C -> нет исходящих связей
```

Цикл A → B → C → A:

```powershell
.\run.bat --package A --repository examples/cycle.json --test-mode
```

```text
Граф зависимостей для A:
A -> B
B -> C
C -> A
```

Несвязанные группы: в результат попадают только A и B:

```powershell
.\run.bat --package A --repository examples/disconnected.json --test-mode
```

Общая зависимость D остаётся доступной через C после исключения B:

```powershell
.\run.bat --package A --repository examples/shared.json --test-mode --filter B
```

```text
Граф зависимостей для A:
A -> C
C -> D
D -> нет исходящих связей
```

Исключение самого корня:

```powershell
.\run.bat --package A --repository examples/repository.json --test-mode --filter A
```

```text
Граф зависимостей для A:
После фильтрации граф пуст.
```

## Демонстрация ошибок

```powershell
.\run.bat --package Bash --repository https://archive.ubuntu.com/ubuntu
.\run.bat --package bash --repository ftp://example.com
.\run.bat --package A --repository missing.json --test-mode
.\run.bat --package A --repository examples/repository.json --test-mode --filter " "
.\run.bat --package bash --repository https://archive.ubuntu.com/ubuntu --test-mode=false
.\run.bat --package Z --repository examples/repository.json --test-mode
```

Повреждённый JSON, неверная структура, повтор имени, ссылка на отсутствующий
ключ, отсутствие реального пакета и ошибки индекса также проверяются тестами.

## Тестирование

```powershell
python -B -m unittest discover -s tests -v
```

Проверяются порядок BFS, циклы, общие зависимости, фильтрация и обход
широких графов, тестовый JSON, однократная загрузка HTTP-индекса, альтернативы
и отсутствующие записи зависимостей. Тесты используют стандартный `unittest`,
подмену сетевых ответов и временные файлы; доступ к интернету не требуется.

## Функции командной строки

| Функция | Назначение |
| --- | --- |
| `validate_package` | Проверяет имя с учётом режима |
| `validate_url` | Проверяет схему, наличие узла, порт и символы URL |
| `validate_file` | Проверяет существование и доступность файла |
| `validate_filter` | Проверяет подстроку фильтра |
| `validate_args` | Проверяет все настройки |
| `parse_args` | Описывает, читает и проверяет параметры |
| `print_graph` | Выводит связи достижимого графа в порядке BFS |
| `run_test_mode` | Читает JSON, выполняет BFS и выводит результат |
| `run_apt_mode` | Загружает индекс Ubuntu и выводит граф |
| `main` | Запускает выбранный режим и возвращает код завершения |

## Функции чтения индекса

| Функция | Назначение |
| --- | --- |
| `get_index_url` | Принимает URL индекса или дополняет корень репозитория |
| `download_index` | Получает байты индекса через urllib |
| `decode_index` | Распаковывает данные и декодирует UTF-8 |
| `parse_field` | Разбирает строку поля Packages |
| `iter_package_records` | Читает записи, разделители и продолжения полей |
| `find_package` | Находит единственную запись выбранного пакета |
| `extract_dependencies` | Извлекает группы Depends и Pre-Depends |
| `get_direct_dependencies` | Возвращает прямые зависимости, используется на этапе 2 |
